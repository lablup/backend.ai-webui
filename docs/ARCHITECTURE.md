# Architecture overview

이 문서는 현행 ADR(Architecture Decision Record)의 색인이다. 진본은 각 ADR 파일(`docs/adr/`)이며,
이 표는 새 해석을 더하지 않는다. `main`에 착지한 ADR은 발효된 결정이고, 코드는 그 결정을 따른다.

## ADR 목록

| ADR | 무엇을 정하는가 |
|---|---|
| [0001 — Explicit project prop contract for leaf components](adr/0001-explicit-project-prop-contract.md) | leaf component는 현재 project를 ambient hook에서 읽지 않고 필수 prop `project`로 받는다. page만 ambient 값을 읽어 넘기고, `null`을 받은 component는 tier마다 정한 동작을 한다. `/admin/*` 화면은 project-agnostic route로 묶이고 ESLint가 그 안에서 `useCurrentProjectValue` import를 막는다. |
| [0002 — Pin set link grammar and a single codec](adr/0002-pin-set-link-grammar-and-single-codec.md) | review overlay의 pin 여러 개는 `#bai=v3` part를 `&`로 이어 붙인 링크 하나로 나른다. 읽는 쪽은 overlay의 codec 하나뿐이고 `pnpm run review-pins` CLI로 노출되며, Claude 쪽 review skill과 Teams transport는 그 CLI를 부른다. |
| [0003 — Committed search index artifact](adr/0003-committed-search-index-artifact.md) | 전역 검색 palette의 인덱스 `react/src/generated/searchIndex.json`은 source에서 생성해 git에 커밋하고, production build는 그 커밋본을 그대로 번들한다. drift는 `scripts/verify.sh`와 `.github/workflows/typecheck.yml`이 다시 만든 뒤 `git status`로 잡고, conflict는 손으로 합치지 않고 다시 만든다. |
| [0004 — Walkthrough stops in the v3 anchor](adr/0004-walkthrough-stops-in-the-v3-anchor.md) | A Stop (한 pin이 무엇이 바뀌었고 무엇을 확인해야 하는지 담는 것)은 v3 anchor에 추가된 optional field 묶음이며 버전은 올리지 않는다. strict resolution, codec 소유의 volatile-query denylist, GitHub 댓글 65,536자 제한이 만드는 20-stop cap, 댓글을 구분하고 idempotent하게 만드는 `bai-walkthrough` marker와 `review-pins parse`의 stop 제외 규칙(resolver가 stop을 finding으로 읽지 않게 만드는 실제 보장), guided mode의 docs PR preview grammar 차용, 그리고 webui 소유 skill이라는 trigger를 정한다. |
| [0005 — Container image meta row](adr/0005-container-image-meta-row.md) | container image 한 개의 identity는 image node의 schema에 맞는 BUI component가 그린다. v2 `ImageV2`는 `BAIImageNodeSimpleTagV2`, v1 `ImageNode`는 `BAIImageNodeSimpleTag`이고, 둘 다 `imageFrgmt`·`withoutTag`·`copyable`만 받아 나머지를 node에서 파생한다. image node가 없는 host 화면은 `ImageTags.tsx`의 `ImageMetaDivider`·`ImageTagTokens`로 같은 행을 각자 그리고, tag chip 판정은 BUI의 `imageNodeTagFacts` 하나다. |
| [0006 — Version-gated field pairs across manager versions](adr/0006-version-gated-field-pairs-across-manager-versions.md) | `data/schema.graphql`은 supergraph 복사본 하나로 둔다. 26.8 매니저와 26.9 매니저가 각각 답하는 root field는 한 document에 함께 두고 옛 field에 `@deprecatedSince`, 새 field에 `@since`를 달아 `graphql-transformer.ts`가 연결된 매니저에 맞지 않는 쪽과 그쪽만 쓰는 variable 정의를 지운다. 그 밖의 분기는 `backend.ai-client`의 feature flag로 고른다. RBAC type 문자열을 비교하는 component는 값을 대문자로 바꿔 비교하고, 매니저가 답한 표기를 그대로 보낸다. role form은 `rbac-single-scope-role` flag로 `CreateRoleInput.scope`와 `scopes` 중 하나를 보낸다. role 목록의 scope 열은 `readRoleScope`가 답한 `extraCount`로만 `+N` badge를 정하고, filter의 scope type 옵션은 그 select가 직접 query를 들고 `Suspense`로 로딩한다. 지금 이 방식을 따르는 RBAC document는 `useCurrentUserProjectRoles`, `RoleNodesFragment`, role drawer의 scope fragment들이고, gate되지 않은 권한 tab의 26.9 동작과 26.8 지원 종료 시 지울 것을 함께 적는다. |
| [0007 — Badge for live values and Token for settled values](adr/0007-badge-for-live-values-and-token-for-settled-values.md) | 값 하나를 chip으로 그릴 때 시스템이 스스로 바꾸는 값(status, 진행 중 표시, ticker, Current·Latest)은 Astryx `Badge`로, 사용자가 편집할 때만 바뀌는 값과 분류 label과 기록된 결과는 Astryx `Token`으로 그린다. 개수는 `Badge`, 점 하나는 `StatusDot`으로 남는다. chip component 이름은 그리는 primitive에 따라 `*Badge`·`*Token`으로 끝나고 "Tag"는 domain 명사로만 쓴다. 색은 `astryxTagVariant.ts`의 `badgeVariantFor*`·`tokenColorFor*`로만 고르고, 붙은 chip 쌍은 `BAIDoubleToken`과 `BAIDoubleBadge` 두 가지다. |
| [0008 — Host-agnostic review overlay client](adr/0008-host-agnostic-review-overlay-client.md) | review overlay client가 dev server에서만 얻을 수 있던 것은 모두 host가 답하는 option이 되었다. 시작점은 import 시점에 아무 일도 하지 않는 `client/boot.ts`의 `bootOverlay` 하나이고, `client/main.ts`는 기본 host로 boot하는 entry로 남아 관찰되는 동작이 그대로다. host는 state source, `bootHash`, `pageChords`, `autoNavigate`, `palette`, `marker`, `expectReactGrab`을 답한다. ADR 0002의 codec 하나는 chrome extension이 `client/*.ts`를 byte 단위로 vendoring하고 sync script의 sha256 기록과 CI의 `--check` gate와 복사한 test suite로 지킨다. extension은 page의 keyboard shortcut과 자동 이동과 host palette를 끄고, storage는 page의 것을 그대로 쓴다. client가 extension의 compiler flag에서 컴파일되는지는 `tsconfig.host.json` gate가 지킨다. |
| [0009 — @lablup/ui-common as the single entry point to Astryx](adr/0009-ui-common-as-the-single-entry-point-to-astryx.md) | `react/`와 BUI의 source는 Astryx를 `@lablup/ui-common`의 subpath로만 import하고, ESLint `no-restricted-imports`가 `@astryxdesign/*` import를 막는다. ui-common 0.2.0 publish 전까지 webui는 `vendor/`의 packed tarball을 `file:` spec으로 설치하고, `@astryxdesign/core`와 `@astryxdesign/cli`는 core가 한 벌만 설치되도록 exact-pinned devDependency로 남으며 `patchedDependencies` key는 version 없는 이름이 된다. ui-common으로 옮긴 component는 Astryx 모양의 props를 갖고, BUI는 같은 이름의 `BAI*` adapter로 frozen antd-v6 props를 옮긴다. ui-common 문자열은 Astryx `useTranslator()`로 찾고 `BAIConfigProvider`가 ui-common locale과 BUI 번역을 한 번 합친다. cascade layer 순서에는 `astryx-theme` 다음에 `ui-common`이 들어가고, agent 지침은 `ui-common agents`가 만드는 `UI-COMMON` block이다. |

## 새 ADR을 적는 방법

언제 ADR이 필요한지는 `.claude/rules/adr.md`가, 파일 이름·제목·절 구성·문장 규칙·착지 전 검사는
`.claude/skills/adr-writing/` 스킬이 정한다. ADR 파일과 이 표의 한 줄과 그 결정을 따르는 코드는 한
PR로 들어간다.
