# Phase 5 — Astryx-native wrapper policy

**Gate:** `bash scripts/verify.sh` → `=== ALL PASS ===`
**Commits:** `58c2e1828`, `f416d39fd`
**Screenshots:** `.pilot/shots/pilot5-*.png`, `.pilot/shots/pilot6-*.png`

New policy applied: **use Astryx directly; create a `BAI*` component only when it
carries real functionality, and base its props on ASTRYX's, never antd's.**

### Renames applied (antd vocabulary → Astryx vocabulary)

`dataSource`→`data` · `columns[].title`→`.header` · `.render(v,rec,i)`→`.renderCell(item)` ·
`.sorter`→`.sortable` · `.required`→`.isRequired` · `.defaultHidden`→`.isHiddenByDefault` ·
`rowKey`→`idKey` · `loading`→`isLoading` · `resizable`→`isColumnResizable` · `size`→`density` ·
`selectedRowKeys`→`selectedKeys` · `getCheckboxProps`→`getIsItemEnabled` ·
`tabList`→`tabs` · `activeTabKey`→`activeTab` · `onTabChange`→`onChangeTab` ·
`open`→`isOpen` · `onCancel`→`onOpenChange` · `okText`→`actionLabel` ·
`okButtonProps.danger`→`actionVariant="destructive"` · `onOk`→`onAction`.
`scroll` and `showSorterTooltip` were **deleted**, not translated.

## Cost: native vs shim

| | edits |
|---|---:|
| JSX call sites rewritten in the pilot graph | **28** |
| Column definitions rewritten (VFolderNodes) | **15** |
| Files touched | 7 |
| tsc rounds to green | **6** |
| Files that would ALSO have needed edits under a *fully* native policy | **11** (9 import `FolderCreateModalV2`; `VFolderNodeListPage` shares `VFolderNodes`) |

The shim approach (Phases 1–4) cost **0** call-site edits for the same components.
Native cost ~43 edits + 6 tsc rounds, and buys a tree with no antd vocabulary left
in the new components.

### The finding that matters most: **the antd ghost relocates, it does not vanish**

The native policy stops at the boundary of the migrated subgraph. `FolderCreateModalV2`
(9 external consumers), `DeleteVFolderModal`, `RestoreVFolderModal` and `VFolderNodes`
(shared with `VFolderNodeListPage`) are APP components whose callers were never
migrated — so they **keep** `open` / `onRequestClose` / antd-shaped `rowSelection` /
`loading` and translate internally. Going fully native there would have pulled 11
unmigrated files into the pilot. **Plan for a translating frontier that moves with the
migration, not for its absence.**

### Unexpected benefit

Dissolving the wrappers **deleted the page's last dependency on the antd token shim** —
`theme.useToken()` is gone from `AdminVFolderNodeListPage` entirely, because Astryx
components carry their own colours. And TypeScript now **rejects** off-scale spacing
(`gap={token.marginSM}`) at the call site instead of the wrapper silently snapping it
(P9). Native APIs convert a class of silent visual drift into compile errors.

## P12 corrected — the real cause of the table bleed

The Phase-4 diagnosis was **wrong**. Measured:
`astryx-table-scroll-wrapper` computes to `margin-top: -24px; margin-bottom: -24px`
(plus the inline pair), applied **unconditionally** in `Table.js`
(`stylex.props(base, containerBleed, ...pluginStyles)`). **There is no prop knob.**

It is **not** "edge compensation": that mechanism
(`Layout/edgeCompensation.stylex`) is `marginInline`-**only** and is opt-in via a
`data-astryx-edge-comp` attribute — and `Table` is not among its consumers
(`Toolbar`, `TabList`, `Tab`, `Button`, `Banner`, `Layout` are).

The **inline** bleed is wanted; the **block** bleed is the bug — the −24px top pulled
the table into the parent's gap (the user-reported "filter and table glued together")
and the −24px bottom dropped it over the pagination bar. Fixed with symmetric
`paddingTop/Bottom: 24` on our wrapper.

Two official alternatives, both rejected and recorded: a table plugin returning `xstyle`
from `transformScrollWrapper` (needs the StyleX **compiler**, which ticket 03 advises
against), and a `defineTheme` override on the themeable class `table-scroll-wrapper`
(compiler-free and official, but **global** — it would also kill the bleed for tables
that are a card's only child, where it is correct).

# Phase 6 — layout fidelity correction (partial)

## Original layout tree (`git show main:…AdminVFolderNodeListPage.tsx`)

```
BAIFlex column gap=md
└─ BAICard variant=borderless title="Folders"
   │   styles.header.borderBottom = none ; styles.body.paddingTop = 0
   │   (NO extra, NO tabList)
   ├─ BAITabs                         ← first child of the card BODY
   └─ BAIFlex column align=stretch gap=sm
      ├─ BAIFlex justify=between wrap gap=sm        ← ONE row
      │  ├─ BAIFlex gap=sm align=start wrap flexShrink:1   (LEFT)
      │  │    BAIRadioGroup · BAIPropertyFilter
      │  └─ BAIFlex gap=xs                                  (RIGHT)
      │       BAISelectionLabel · delete/restore · fetch-key · Create folder
      └─ VFolderNodes
```

## Divergence table

| # | Original | Phase 4 had | Fixed |
|---|---|---|---|
| 1 | Card header = title only | title + `extra` (refresh, create) | ✅ reverted |
| 2 | Tabs are the card **body**'s first child | card header `tabList` slot | ✅ reverted |
| 3 | Refresh + Create at right of the action row above the table | in card `extra` | ✅ moved back |
| 4 | Left group has `flexShrink: 1` | dropped by the BAIFlex codemod | ✅ restored |
| 5 | `styles.header.borderBottom: none` | n/a (Astryx has no header divider) | — no-op |

**Principle recorded for the spec: during a migration, per-page ORIGINAL FIDELITY beats
a generic convention.** `use-bai-card.md` says card-scoped actions belong in `extra`;
this page does not do that, and the convention is for NEW cards. Applying it during a
port silently changes the UI and the user notices immediately.
